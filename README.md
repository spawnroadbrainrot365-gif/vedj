# VIDORA — مكتبة فيديوهات

مشروع Express بواجهة عربية، صفحة عامة للفيديوهات، مشغل فيديو، ولوحة إدارة.

## الملفات

كل ملفات المشروع موجودة في الجذر مباشرة، بدون مجلدات فرعية.

## التشغيل محلياً

1. ثبّت Node.js 20 أو أحدث.
2. افتح Terminal في مجلد المشروع.
3. نفّذ `npm install`.
4. عدّل إعدادات الاتصال وبيانات الإدارة مباشرة داخل `server.js`. لا تحتاج إلى ملف `.env`.
5. نفّذ `npm start`.
6. افتح `http://localhost:3000/Home`.

## النشر على Railway

1. ارفع جميع الملفات إلى مستودع GitHub.
2. أنشئ مشروعاً جديداً في Railway واربطه بالمستودع.
3. من Variables أضف المتغيرات التالية:
   - `FIREBASE_URL`: رابط قاعدة البيانات الأساسي الذي يعطيك إياه مولّدك، مثل `https://example.com/Firebases/123456789`، بدون `.json`.
   - `ADMIN_CODE`: رمز الإدارة.
   - `ADMIN_PASSWORD`: كلمة مرور الإدارة.
   - `SESSION_SECRET`: سلسلة عشوائية طويلة وسرية.
4. Railway سيشغّل `npm start` تلقائياً وفق إعدادات المشروع.

## قاعدة البيانات

المشروع يستخدم نفس نمط REST الموجود في سكربت Express الذي أرسلته:

- قراءة القائمة: `GET /Videos.json`
- إضافة: `PUT /Videos/{id}.json`
- تعديل: `PATCH /Videos/{id}.json`
- حذف: `DELETE /Videos/{id}.json`

يتم إرسال طلبات قاعدة البيانات من الخادم حتى لا نضع رابط قاعدة البيانات في كود المتصفح.

## ملاحظات

- تسجيل دخول الإدارة يصدر رمز جلسة موقّعاً، ويُحفظ الرمز في LocalStorage لمدة 7 أيام. لا تُحفظ كلمة المرور في المتصفح.
- هذا المشروع لا يستضيف ملفات الفيديو نفسها؛ يجب أن يكون `VideoUrl` رابط فيديو مباشر قابل للتشغيل في المتصفح (مثل MP4 أو مصدر متوافق).
- الصورة المصغرة اختيارية.
- قاعدة البيانات الموجودة في سكربت المولّد الذي أرسلته تحفظ البيانات في ذاكرة السيرفر فقط؛ إذا أُعيد تشغيل ذلك السيرفر فقد تضيع البيانات. استخدم قاعدة بيانات دائمة أو تأكد من آلية الحفظ في الخدمة التي تستضيفها.
- تأكد أن خدمة قاعدة البيانات متاحة عبر HTTPS من Railway.
- لا تضع أسرار الإدارة في GitHub. ضعها في Railway Variables.
